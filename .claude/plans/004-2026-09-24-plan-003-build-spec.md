### B2. New `scripts/lib/freshness.ts`

```ts
export const FRESHNESS_PATH = "state/freshness.json";
export const FRESHNESS_STATUSES = ["fresh", "due", "stale", "final", "unscheduled"] as const;
export const FreshnessEntrySchema = z.object({
  lastCheckedAt: z.iso.datetime().nullable(), // newest ok/facts check over the race's source URLs; null: never checked
  lastChangedAt: z.iso.datetime(),            // the race file's updatedAt (index lastModified)
  cadence: z.enum(CADENCES),                  // most frequent `check` among its sources' sites
  dueAt: isoDate.nullable(),                  // Vietnam date of lastCheckedAt + cadence; null when manual or never checked
  final: z.boolean(),                         // the race's last day (endDate ?? date) is before today in Vietnam
});
export const FreshnessSchema = z.record(z.uuid(), FreshnessEntrySchema);
export function buildFreshness(index: IndexEntry[], checks: Checks, config: SitesConfig, now: Date): Record<string, FreshnessEntry>;
export function freshnessStatus(e: FreshnessEntry, now: Date): FreshnessStatus;
```

- A source URL's site: `siteForUrl(config, url)`; no site → `manual`.
- Only checks with `status` `ok` or `facts` count. `rejected` and `error` are not checks of the data.
- "Most frequent" = smallest `CADENCE_DAYS`.
- `freshnessStatus`, in this order:
  1. `final` → `"final"` (after race day a race is never checked again and never stale).
  2. cadence `manual` → `"unscheduled"`. *(003 lists four statuses; a race only a manual site has has no schedule to be late for, and calling it fresh would be a lie. The API shows `lastCheckedAt` next to it.)*
  3. never checked → `"stale"`.
  4. more than 2 × cadence days since `lastCheckedAt` (exact milliseconds) → `"stale"`.
  5. today in Vietnam ≥ `dueAt` → `"due"`.
  6. otherwise `"fresh"`.
- Use `vietnamDate` from `state.ts`; don't write a second one.

## Stage C: location (plan 003, Part 2)

### Decisions made while writing this stage (2026-09-24, supervisor; the user was away)

- **The point and everything derived from it live in a cache, `state/geo.json`,** keyed by a location key (below). `npm run geo` fills it (network: Nominatim, routing). Composing a race (sync, renormalize) only *reads* the cache, so it stays pure and re-runnable. The race's `geo` field is the cache entry for its location key, or `null`. *(003 had the codes computed in reconcile; with the point in a cache it's the same thing, and the heavy boundary files are only loaded by `npm run geo`.)*
- **Boundaries:** the ward polygons are 621 MB, too big to commit. `npm run geo:ref` downloads them once to a git-ignored cache at a pinned commit, and commits only a compact, simplified copy (`ref/wards-2025.json.gz`) plus the code/name tables. Point → ward is then offline, from committed files.
- **No ORS key yet** (none in `.env` or the repo's secrets). Routing tries, in order: OpenRouteService when `ORS_API_KEY` is set; else the public OSRM demo server (`router.project-osrm.org`, light use: ≤ 1 request/second, one `table` request per race, results cached, a proper User-Agent); else straight-line km (`method: "straight_line"`, `minutes: null`). The same code runs with ORS once the user adds a key.
- **Islands:** the 13 special zones (`wardType` "Đặc khu") except Vân Đồn (road bridge) are `access: "flight_or_ferry"`, and get straight-line km, no minutes.
- **Places:** `config/places.yaml` drafted by the supervisor (13 places, old district codes checked against the reference CSV). Not reviewed by the user yet.

### C2. `scripts/lib/geo.ts` (pure, no network)

```ts
export type Place = { id: string; name: string; center: [number, number]; radiusKm: number; legacy: { districts: string[] } };
export function loadPlaces(path = "config/places.yaml"): Place[];           // zod-validated
export function haversineKm(a: [number, number], b: [number, number]): number;
export function locate(lat: number, lng: number): { current: { province: string; ward: string | null }; legacy: {...} | null; special: boolean } | null;
export function locationKey(location: { venue: string | null; city: string | null }): string | null;
export function parseMapsUrl(url: string): [number, number] | null;
export function isNear(geo: Geo, place: Place): boolean;
```

- `locate`: bbox prefilter, then point-in-polygon (ray casting, holes respected) over the wards. No polygon contains it (a beach or pier just offshore) → the ward whose polygon has the nearest vertex within 3 km; else `null`. `current.province` from the ward. `special` = the ward's type is "Đặc khu" and it isn't Vân Đồn (`06994`).
- Legacy: among legacy wards with `newWard === current.ward`, the one whose centre is nearest the point; none → the nearest legacy ward centre in the same new province. `legacy = { province, district, ward }` from that row.
- Loads the ref files once (lazy, module-level).
- `locationKey`: `foldVietnamese` of `venue` and `city` joined with `" | "`, whitespace collapsed; `null` when both are null. Two races at the same venue text share a cache entry.
- `parseMapsUrl`: `@lat,lng`, `?q=lat,lng`, `query=lat,lng`, `!3dLAT!4dLNG`, or a bare `"lat, lng"`. Short links (`maps.app.goo.gl`, `goo.gl/maps`) return `null` here (resolved by the network step).
- `isNear`: straight-line distance from `place.center` ≤ `radiusKm`, or `geo.legacy?.district` is in `place.legacy.districts`.

### C3. The cache and the race field

- `state/geo.json`: `Record<locationKey, GeoCacheEntry>`, sorted keys (`serializeSorted`). `GeoCacheEntry = { geo: Geo | null; query: string; at: iso datetime; note?: string }`: `geo: null` means "looked up, not found" (so it isn't looked up again every run); `note` says why ("no Nominatim result", "virtual race").
- `scripts/sync.ts` `composeRace`: `geo` = `cache[locationKey(fields.location)]?.geo ?? null`, **unless** `overrides.geo` exists (then the override, like any canonical field). The cache is read once per sync from the store (`state/geo.json`; missing = `{}`) and passed in. Add `geo` handling to `planEdit` the same way.
- A race whose `types` or name says virtual (`/virtual|online|trực tuyến/` folded, in name or venue) → `geo: null` without lookup, cache note "virtual race".
- `scripts/validate.ts`: check `state/geo.json` against its schema.
- `scripts/edit.ts`: allow `geo` as a field: value `{"lat": …, "lng": …}` becomes a full `Geo` via `locate` + routing, with `source: "manual"`, `precision: "venue"` (so a manual point needs network; say so in the help text).

### C4. Network step: `scripts/geo.ts` (npm `"geo"`) and `scripts/lib/geocode.ts`

For every race in the local index whose location key isn't in `state/geo.json` (or all with `--refresh`):

1. **Point**, first that works:
   - a maps URL: any source's `extracted.pages[].json.mapsUrl` or `extracted.facts.mapsUrl`, or a race `links[]` URL on a Google Maps host. Short links: follow redirects (HEAD, then GET) and parse the final URL. → `source: "maps_link"`, `precision: "venue"`.
   - Nominatim search: `https://nominatim.openstreetmap.org/search?format=jsonv2&countrycodes=vn&limit=1&addressdetails=1&q=<query>`, header `User-Agent: openrace-data/0.1 (https://github.com/openracevn/openrace-data)`. At most 1 request per second (sleep between calls, never parallel). Queries in order until one returns a result: `venue, city`; `venue`; `city`. `source: "nominatim"`; `precision`: `"venue"` if the result's `addresstype` / `type` is finer than a ward (anything but `state`, `province`, `city`, `county`, `municipality`, `suburb`, `quarter`, `village`, `town`, `administrative`), `"ward"` for suburb / quarter / village / town / municipality, `"province"` for state / province / city / county. Results outside Vietnam's box → treat as no result.
   - none → cache `geo: null`, note "no point found".
2. **Codes:** `locate(lat, lng)`; `null` → cache `geo: null`, note "point outside Vietnam's wards".
3. **Access:** `special` → `flight_or_ferry`, else `road`.
4. **fromPlaces:** for all 13 places. Road access and precision not `province`: one routing call with the race as the single destination and the 13 places as sources:
   - ORS (`ORS_API_KEY` set): `POST https://api.openrouteservice.org/v2/matrix/driving-car`, body `{ locations: [[lng,lat] × 14], sources: [1..13], destinations: [0], metrics: ["distance","duration"], units: "km" }`.
   - else OSRM demo: `GET https://router.project-osrm.org/table/v1/driving/<lng,lat;…>?sources=1;…;13&destinations=0&annotations=distance,duration`, 1 request/second, same User-Agent.
   - `km` rounded to 1 decimal, `minutes` rounded to an integer, `method: "road"`. A null cell, or a snapped destination more than 5 km from the point → that place gets straight-line.
   - Otherwise (islands, province precision, routing down): `km` = haversine rounded to 1 decimal, `minutes: null`, `method: "straight_line"`.
5. Write `state/geo.json` after every race (so a crash loses nothing). `--dry-run` prints without writing; `--limit N` stops after N lookups.
6. At the end print: counts by source and precision, the races with no point, the races with province precision, and how many used which routing method. The supervisor pastes this into the summary.

`scripts/check.ts` and `scripts/agent-read.ts` (commit): before planning the sync, run the network step for the races about to be written whose location key isn't cached (same function), and add `state/geo.json` to the commit's state files. Failures there only log; the race is written with `geo: null`.

### D3. Price on a date: `src/lib/price.ts`

```ts
export type PriceStatus = "on_sale" | "not_yet_open" | "ended" | "no_price";
export type PriceAt = { price: number | null; tier: string | null; kind: string | null; validTo: string | null;
                        next: { price: number; tier: string; from: string } | null; status: PriceStatus };
export function priceAt(prices: PriceTier[], course: string | null, at: string, opts: { group: boolean; audience: "resident" | "non_resident" | null }): PriceAt;
```

- Candidate tiers: `distance === course` or `distance === null`. Leave out `group` tiers unless `opts.group`. Audience: tiers with `audience` null, plus `resident` by default, or plus the asked audience when `opts.audience` is set.
- On sale at `at`: `(from === null || from <= at) && (to === null || at <= to)`. A tier with neither date counts as on sale (the source gave a price without a window).
- `on_sale`: the cheapest on-sale tier (ties: earliest `to`). `validTo` its `to`. `next`: the cheapest tier whose `from` is after `at` (null if none).
- None on sale, and some tier starts after `at` → `not_yet_open`, `price` null, `next` = the earliest-starting one.
- None on sale and every tier ended → `ended`, `price` null.
- No candidate tiers → `no_price`.
- Keep `priceFrom` as it is.

### D4. `/races` (list and search) parameters (`races.schema.ts`, `races.services.ts`)

Keep existing parameters, rename `dateFrom`/`dateTo` semantics to **overlap**: a race matches when `date <= to` and `coalesce(endDate, date) >= from` (params `from` and `to`; keep `dateFrom`/`dateTo` as aliases). New:

| Param | Meaning |
|---|---|
| `near=<place>` | `exists race_place` with that place and `near = 1` |
| `fromPlace=<place>` | adds `fromPlace: { place, km, minutes, method }` to each race |
| `province=<code or name>` | current province code; a name is matched folded against `admin_units` (current, then legacy → its current province via the races' `legacy_province_code`) |
| `at=YYYY-MM-DD` | the date for prices; default today in Vietnam (`vietnamDate`) |
| `distance=<label>` | races with a course of that label (folded compare, `21`, `21k`, `21km`, `half` all mean `21km`; reuse `normalizeDistance`), and prices are for that course |
| `maxPrice=<int>` | races whose price (below) is ≤ this and status `on_sale`; replaces `priceMax` (keep it as alias) |
| `group=true`, `audience=resident\|non_resident` | passed to `priceAt` |
| `fresh=true` | leave out races whose freshness status is `stale` |
| `after=<race id, slug, or series id>` | races whose `date` is after that race's last day; for a series, its latest edition that has started (date ≤ today) |
| `sort=date\|price\|distance_desc\|distance_asc\|travel_time` | default `date` (today's order). `travel_time` needs `fromPlace` (400 otherwise). |

- Each race in a list gets `priceAt` (for `distance` if given, else the cheapest `on_sale` course; if none on sale, the first course's status by the order `not_yet_open`, `ended`, `no_price`), and `courses[]` each get their own `priceAt`.
- Sorting: `price` ascending, races without an on-sale price last; `distance_desc` by `max_meters`, `distance_asc` by `min_meters` (or that course when `distance` is set), nulls last; `travel_time` by `race_place.minutes`, then `km`, straight-line-only races after road ones, races without geo last.
- Implementation: filter in SQL on the indexed columns (date window, type, province, near, series, organizer, status, name terms), load the matching rows (upcoming is tens of rows; `when=all` is ~300), then compute prices, apply `maxPrice`/`fresh`, sort and paginate in JS. Don't try to compute prices in SQL.
- The list response gets a `meta` object: `{ at, excluded: { noPrice: n, notOnSale: n, stale: n, noGeo: n } }`: how many races the filters dropped **only** because a price, point or fresh check was unknown or failing (trust principle 3: say how many were left out and why).
