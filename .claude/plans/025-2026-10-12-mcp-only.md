Date: 2026-10-12. Status: decided by the user 2026-10-12 (narrowed twice the same day: first "MCP only, the API is not public", then "no OpenRace homepage, launch on the Perxel website"); not built yet. Spans openrace-api, openrace-mcp and openrace-data. **openrace-web is archived, not changed or deleted.** It supersedes [plan 024](024-2026-10-12-launch-readiness-today.md) and [plan 022](022-2026-09-29-web-home-and-content-depth.md), and amends [plan 021](021-2026-09-29-mvp-launch-checklist.md) (see the end).

The goal is one thing: **the data, the API and the MCP server work together, end to end, without anyone tending them.**

## Roadmap fit

A change of direction, confirmed by the user and recorded in the roadmap's change log (2026-10-12) and in "Who we serve, and why not web traffic".

- **Path step 5 changes.** The MCP server is the product and the only public way in. The API is internal: only openrace-mcp and the openrace-data sync reach it. There is no OpenRace website; OpenRace is presented on the Perxel website (perxel repo, outside this plan).
- **Path step 4 (stats)** has no web page now. The numbers stay reachable through the MCP tools (e.g. `get_data_completeness`); charts, if wanted, belong to the Perxel website later.
- **Constraints:** no hosted chatbot (a paid LLM breaks the budget); people bring their own assistant through MCP. No website means no web hosting cost.
- **Trust principles:** unchanged. Principle 2 ("visibly fresh") is met by the MCP tools, which return freshness and sources on every race.

## Why: the decision on web traffic (2026-10-12)

The user's decision, from an owner's review on the day the website went down (Cloudflare error 1102: the Next.js Worker went over the free plan's 10 ms of CPU per request).

**Web traffic is not what benefits OpenRace.** A visit is only worth something if it turns into something. A runner visiting the site turns into:

- **money:** none. Ads, ticket sales and paid listings are non-goals, and OpenRace is non-commercial;
- **accounts or community:** none, also non-goals;
- **better data:** almost none. Visitors don't send corrections, and there is no channel for them to;
- **cost:** real. Every page view runs our code, and that is what took the site down.

**What does benefit OpenRace:**

1. **Being the source other systems use:** AI assistants and other MCP clients connecting to our MCP server. One integration showing our data to thousands of runners is worth more than those runners visiting us, and it costs us nothing to serve.
2. **Perxel's credibility:** a clear, working data product with an MCP server is a portfolio piece. For that, the right people need to see it work, not crowds.
3. **The data getting better:** that's the moat, and it drives 1 and 2. Visitors don't improve it.

Assistants reach the data through MCP, not by crawling race pages. `llms.txt` and the website say what OpenRace is and how to connect, at no running cost.

**Success is measured by:** MCP tool calls, the number of distinct MCP clients, and data completeness and freshness. **Not page views.**

**What we give up, on purpose:** Google search traffic from runners searching "giải chạy tháng 11", and a shareable page per race. If a future plan wants these back, it has to show what that traffic turns into, against the list above.

## How the three pieces fit (as of 2026-10-12)

```
openrace-data (GitHub, public)
  └─ push to main → Main workflow: validate → notify:sync
        └─ POST SYNC_WEBHOOK_URL (X-Sync-Secret) → openrace-api
openrace-api (Worker + D1)
  ├─ pulls changed files from GitHub itself; daily cron 00:30 UTC
  └─ answers openrace-mcp through the service binding `API`
openrace-mcp (Worker, public: https://openrace-mcp.bmp.workers.dev)
  └─ the only door for assistants (Claude, ChatGPT, Cursor, other MCP clients)
```

What "internal API" has to respect:
- The sync webhook comes from GitHub Actions over the internet, so the API keeps a public URL **for that one route only**, guarded by `X-Sync-Secret`. Turning `workers_dev` off would break the sync.
- Service binding calls reach the same `fetch` handler, so the lock must let openrace-mcp through (a shared secret header sent by the MCP, or a check that tells binding calls apart).
- The API reads the data repo from GitHub. It works because the repo is public; if the repo ever goes private, the API needs a GitHub token first.

## Steps

### 1. Archive openrace-web: first, delete nothing
- Tag the current full site: `archive/full-site-2026-10-12` on `main`, pushed. Keep branch `fix/isr-cache-cpu-limit` pushed as it is. No code is removed.
- The Worker `openrace-web` is down anyway (error 1102). Ask the user before removing the deployment or the KV namespace `openrace-web-inc-cache`; the code can be redeployed from the tag.
- Remove openrace-web from the `Main` workflow and anything else that triggers a web rebuild.

### 2. Make the API internal (openrace-api)
- Every route except the sync webhook answers 404 unless the request carries the internal secret (or comes through the MCP binding). The public `/reference`, the OpenAPI spec and `ALLOWED_ORIGINS` go away. The rate limit stays as a guard.
- openrace-mcp sends the internal secret on its binding calls; `API_URL` stops pointing at a public URL that MCP clients could find.
- Check: a plain `curl` of the API's workers.dev URL returns 404; the webhook still works with the secret; every MCP tool still answers.

### 3. The end-to-end check: data → API → MCP
- Push a small real data change in openrace-data; confirm `Main` validates, `notify:sync` brings `remaining` to 0, and the change shows in the matching MCP tool within minutes.
- Confirm the API's daily cron still resyncs, and that a sync failure fails the job loudly (Discord).
- Live assistant check (plan 005 step 5): the roadmap questions, in Vietnamese and English, through Claude connected to the MCP server; fix what breaks. Repeat with ChatGPT and Cursor if they connect.
- Keep this as a repeatable script or checklist (`npm run` in openrace-data or a test in openrace-mcp) so it can run again after any change.

### 4. Open the MCP server (openrace-mcp)
- `llms.txt` and a short about text served by the MCP server itself: what OpenRace is, the MCP URL, how to connect in Claude, ChatGPT and Cursor, license and attribution.
- LICENSE files: CC BY 4.0 for the data (attribution "OpenRace by Perxel"), MIT for the code.
- Listing: the official MCP registry (`server.json`), Smithery and other MCP directories. The MCP URL is the one to publish; if it moves to a Perxel subdomain, do that before listing.
- Hand the Perxel website (a separate repo) the facts it needs: the MCP URL, the connect snippets, example questions. Building that page is outside this plan.

### 5. Data fresh without effort (openrace-data, carried over from plan 024)
- Bring upcoming races up to date with `update-race` (on 2026-10-12, 40 of 44 non-final races were overdue, and 5 upcoming ActiUp races were missing).
- A daily free discovery job (ActiUp API, iRace and 5BIB listings; plain fetch, 0 credits): new races as facts-only files, refreshed facts on known ones, and a Discord digest of what needs a full read.
- A Discord alert when `validate` fails on `main`.

### 6. Measure what matters
- One place that shows, per week: MCP tool calls, distinct MCP clients, and the completeness snapshot. Source: openrace-mcp's `mcp_openrace` dataset, plus the completeness snapshot.

## Decisions (settled by the user, 2026-10-12)
1. **MCP only.** The API is internal: reachable by openrace-mcp and the data sync, nothing else. No CORS, no public API docs, no data catalogues.
2. **No OpenRace website.** OpenRace launches on the Perxel website. openrace-web is **archived, not deleted** (step 1).
3. **No hosted chat UI** (considered and turned down twice): assistants connect through MCP.
4. Licenses: **CC BY 4.0** for the data (attribution "OpenRace by Perxel"), **MIT** for the code.
5. Non-commercial, with Perxel as attribution only: follows the roadmap constraint.
6. The openrace-data repo **stays public for now** but isn't promoted. The API depends on it being public (see "How the three pieces fit").
