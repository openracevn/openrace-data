# Day summary: 2026-09-23

The first day of openrace-data: from an empty repo to a working data pipeline with 5 races, live Discord notifications and a synced openrace-api. Current state and next steps are in [status.md](status.md); the reasons behind each choice are in [decisions.md](decisions.md).

## Where we ended up

- **Sources:** ActiUp (Vietnamese pages, primary for every field) and bibchung.pro (a second place to buy, with the group discount `groupPriceMin`), both extracted by Firecrawl (5 credits per page). OpenRace can also set fields itself (overrides) and add races no site lists (source `openrace`).
- **Runs:** `npm run check` locally or the **Check races** workflow (modes: discover / refresh / race / daily). Each run makes one commit straight to `main`. **The daily schedule is off**; everything is manual until the data is trusted.
- **On each data push:** `validate`, then a Discord summary (with links to each race's sources and JSON), then an openrace-api resync (authenticated with `X-Sync-Secret`, repeated until `remaining` is 0).
- **Data:** 5 races. Tết Run Miền Nam 2027 has both sources (21km, from 678,000, group price 542,000).
- **Contract:** `schemaVersion` 1, JSON Schema in `schema/`, sanity bounds. Every change since has been additive.
- **Tooling:** `npm run edit` (overrides, hand-entered races), `npm run renormalize` (re-derive without scraping), and the `check-race` skill for any single-race task.

## Problems found in real runs, and their fixes

- **The ActiUp listing sometimes renders before its events load.** The first real run found 0 races and reported success. Fix: an empty listing is retried 3 times, then the run goes red.
- **Race pages sometimes render empty** (`pageKind: none`). The model once invented a whole race from an empty page. Fix: the prompt asks for `none`, those pages are retried after 3 days, and a manual retry works (Lâm Đồng Trail 2024 needed one).
- **A price stored as a distance** (`"Chỉ từ 678.000đ"`). Fix: a normalization filter plus schema bounds; the stored data was fixed with `renormalize` (no scraping).
- **bibchung prices swapped** (the discounted price reported as `priceMin`) and the **event name reported as the organizer.** Fix: a tighter prompt with an example, plus code guards. Re-tested: the prices are now correct.
- **A re-check that changed nothing left no trace of the model output.** Fix: every run prints each page's raw extraction to the log.
- **A source change under an override was lost.** Fix: it's recorded, and Discord shows "sources now say … (override kept)".

## Facts learned about the sources

- **ActiUp** pages render in the browser. There's a free public listing API: `api.actiup.net/v2/content/events/paging` (301 sports events, 40 upcoming on this date). It has exact dates, prices, sold-out status and registration close dates, but no distances. ActiUp's own categories exist only on old events.
- **bibchung** pages render on the server; plain curl works. The listing is paginated and there's a sitemap (12 events). Each price row reads `tier · distance · regular price · bibchung price`.
- **Firecrawl:** 1 credit per page, +4 for AI JSON extraction; about 10 requests/min on the current plan; no cheaper way to have one AI call read two pages.
